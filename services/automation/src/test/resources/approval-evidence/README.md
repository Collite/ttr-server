# Released writer approval fixture

Generated by the **published ttrp 0.18.9 distribution** (internal grammar/v0.18.9,
Core merge 975adbd). The writer maps package-qualified order fields and supplies
an optional state default, with all five required order attributes mapped. A wired hold action
uses qualified key, set and transition refs; both update and transition effects are checked. A second wired action references the injected stdlib
`automation.obligation.state`, testing the complete reconciled package map.

`ApprovalFixture` overlays the action model and complete generated bundle onto
`bundles/hartland`, then loads it from a temporary `automation-bundles-*/branch`
checkout. No directory named `hartland` is needed for Server approval resolution.
The ER qnames still have empty package identity; declared packages come from the
loader. The generated manifest and dependency hashes are used unchanged. The real-ledger regression
opens and evaluates the governed writer, checking the released state in both the effect row
and would-text, plus the held transition and held_for update; a subsequent metadata-only default edit cannot add ledger work.

To regenerate, pass the installed published CLI path:

```sh
python3 services/automation/src/test/resources/approval-evidence/regenerate.py /path/to/ttrp-cli-0.18.9/bin/ttrp-cli
```

Add `--unqualified` to regenerate the companion under `unqualified/`. It uses the same published
compiler and real evidence with unqualified refs, and runs through the pinned path in a second
real-ledger Open/evaluate case.

`db.ttrm` and `binding.ttrm` provide the producer's minimal Query binding. The
Server approval test needs only the existing ER/world fixture, overlaid action
model and generated bundle. Native preview remains separate from physical writes.
A same-qname project entity can replace a stdlib entity in today's reconciler
(Core#294 package-identity limitation); that missing qualified dependency refuses
approval rather than falling back to the project entity.

The `generated-ids/` variant adds a qualified `reorder_proposal` bigint key and two identical writer
wirings with `generated: bigint_id_v1`, pinned run and explicit state defaults. Its checked-in v1 evidence
is produced unchanged by the released CLI. Regenerate with:

```sh
python3 regenerate.py /path/to/ttrp-cli-0.18.9/bin/ttrp-cli --generated-ids
```

The real-ledger test goes through governed Open/evaluate, checks key/row/action/would-text agreement and
idempotent retry, then close/restart persistence. Editing the source under old evidence refuses before
another claim. This fixture does not perform physical model writes or certify the live H-3 recipe.
